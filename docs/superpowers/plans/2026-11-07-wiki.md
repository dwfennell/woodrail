# Woodrail wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Static wiki pages generated from the game's tables, deployed at `/woodrail/wiki/` with the Pages build.

**Architecture:** `src/wiki/data.ts` reads the game's tables into a plain `WikiData` model; `src/wiki/pages.ts` renders
it to `Page[]` (path, title, description, html); `scripts/wiki.mjs` loads `pages.ts` through Vite's SSR loader with the
project config and writes files. Nothing in the game imports `src/wiki/`.

**Tech Stack:** TypeScript, Vite 8 SSR module loading, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-07-wiki-design.md`

## Global Constraints

- No change to the game's runtime: no file under `src/` other than `src/wiki/` changes.
- Only built research rows (`plan === undefined`) get pages, and planned rows are never linked or named.
- Every page links to `https://dwfennell.itch.io/woodrail?ref=wiki`.
- Site base `https://dwfennell.github.io/woodrail/wiki/`; pages at `<section>/<slug>/index.html`, links relative.
- No JavaScript on the pages; one `style.css`.

## Review Focus

- A research row whose `needs` names a planned row: the page must not link to or name it (test: no link to a missing page).
- A good no wagon carries or no industry makes (mail, cocoa from boats): page still says something true, not an empty list.
- A label with `&`, `<` or quotes ("Carpenter's yard"): escaped in titles, descriptions and body (test: no raw `'` in attributes breaks; titles round-trip).
- Two items with the same slug (a car and a look both "tank"): paths are unique (test).
- An industry with no recipe cycle (warehouse, harbour, airport, wind turbine): its page explains what it does without "makes 0".

### Task 1: Data model

**Files:** Create `src/wiki/data.ts`.

**Interfaces:** Produces `wikiData(): WikiData` with `rows`, `industries`, `goods`, `engines`, `wagons`, `explainers`,
each item `{ slug, name, ... }`, plus `pathOf(section, slug)`.

- [ ] Rows from `BLUEPRINTS` filtered by `built`; costs from `costOf`, study time `STUDY_SECONDS[tier]`, unlocks from `unlocksOf` + `THING_RULES` labels, leads-to by reverse `needs`.
- [ ] Industries from `INDUSTRY_GROUPS[0].items` (role via `INDUSTRY_ROLE`, recipe `RECIPES`, site `SITE_RULES`, price `THING_RULES`, row from rule's `tech`).
- [ ] Goods from `CARGO_KINDS`; makers/takers by `gives`/`takes` of `chains.ts`, plus towns from `RECIPES.town`; wagons by `wagonsFor`; research rows whose cost uses it.
- [ ] Engines from `TRAIN_ITEMS` with one car `engine` (or a look in `ENGINES`), wagons from single-car items that aren't engines.
- [ ] Explainers from `EXPLAINERS`.

### Task 2: Pages and test

**Files:** Create `src/wiki/pages.ts`, `src/wiki/style.css`, `src/wiki/wiki.test.ts`.

**Interfaces:** `buildWiki(): { pages: Page[]; sitemap: string; css: string }`, `Page = { path; title; description; html }`.

- [ ] Test first: every built row and every `INDUSTRY_GROUPS` item has a page; every good and explainer too; unique paths; non-empty title and description ≤ 160 chars; every `href` that's relative resolves to a page path; every page contains `?ref=wiki`; no planned row's label appears.
- [ ] Render home, six index pages and one page per item; inline good icons from `src/icons/*.svg` (by code point of `GOODS_ICON`).
- [ ] Run `npx vitest run src/wiki` → PASS.

### Task 3: Script, deploy, look

**Files:** Create `scripts/wiki.mjs`; modify `package.json` (`"wiki"`), `.github/workflows/deploy-pages.yml` (step after build), `AGENTS.md` (command line).

- [ ] `npm run wiki -- --out <dir>` writes pages, `style.css`, `sitemap.xml`.
- [ ] Serve the output and check home, a row, an industry, a good at 390 and 1440 px in the browser pane.
- [ ] `npm run typecheck`, `npm test`, commit, push, PR.
