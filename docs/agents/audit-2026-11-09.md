# Consolidation audit, 2026-11-09

An audit only: no game code changed. Base: `11bc66e` (main after the consolidate-2 merge). The aim is better
structure, less duplication, less dead code, with **no change in behaviour**. Each item below is meant to be one small
branch that lands on its own.

How it was measured (all re-runnable):

- **Dead code:** `npx knip` was blocked in this container: it downloads a package, and the sandbox's rule on outside
  code refused it. Instead, a stand-in script built the import graph and an export reference count from the repo's own
  files. It reads every `import`/`export … from`, `import()`, `ssrLoadModule()` and the e2e suites' in-page
  `import("/src/…")`. Files that are namespace-imported or dynamically imported were treated as fully used, so the
  counts are a **lower bound**. Every name it reported was checked again with `grep -rlw <name> src scripts tools
  catalogue bench`. Re-run `npx knip` where the network allows and compare.
- **Unit tests:** `npx vitest run --reporter=json`. 373 files, 6,546 tests: 6,496 passed, 50 skipped, 0 failed. 450 s
  wall on 4 cores.
- **Long fuzz:** `npm run fuzz:long -- --shards 3` (200 seeds × 1800 s), run to check the known-break lists: all
  passed (§6).
- **Mutation testing:** a two-tier runner over the seven shared modules (§7).
- **The rest:** grep counts. The commands are given beside each number.

Sizes: `src/main.ts` 7,415 lines, `src/game/interaction.ts` 6,639, `src/ui/hud.ts` 3,329, `src/economy/economy.ts`
3,163, `src/economy/sections.ts` 2,967, `src/sim/sim.ts` 2,951. The e2e suites are 71 files and 36,530 lines
(`find scripts/e2e tools/e2e -name '*.mjs' | xargs wc -l`).

### 1. One shared e2e helper set: `scripts/e2e/lib/e2e.mjs`

**Evidence** (full tables in the e2e section below):

- Helpers that 71 suite files define for themselves:
  - `check` in 66 files.
  - `settle`/`settled` in 58. 39 of them are the same line,
    `Promise.race([woodrail.settled(3), new Promise(r => setTimeout(r, 20000))])`, which goes on silently when the
    20 s wins (`tools/e2e/airport.mjs:54`).
  - `shot` in 48. Only 8 of 48 use `lib/shot.mjs`.
  - `frames` in 28.
  - The tap family (`tap`, `tapOn`, `tapButton`, `tapped`, `pressAt`, …): 104 definitions in about 60 files.
  - World to screen (`onScreen`, `worldAt`, `screenOf`): 32.
  - The boot header (vite `createServer` plus `chromium.launch` with the SwiftShader args) is copied into 67 files,
    about 2,130 lines.
- Only 22 of 71 files import `scripts/e2e/lib`. `lib/aim.mjs`, written to replace the fixed world points, is used by 1
  file (`tools/e2e/warehouse.mjs`).
- **Silent taps:**
  - `tools/e2e/engine-names.mjs:54` (`if (!at) return false;`), `tools/e2e/new-game.mjs:48` and
    `tools/e2e/locked-tiles.mjs:84` return false.
  - The 14 `tapped()` copies end in `.catch(() => {})`: `tools/e2e/airport.mjs:58`, `signals.mjs:56`,
    `warehouse.mjs:53`, `water.mjs:61`, `leftovers.mjs:68`.
  - Only 5 tap definitions throw on a miss (`scripts/e2e/touch.mjs:51`, `:1467`, `:5234`, `cloud.mjs:134`,
    `click-place.mjs:704`).
- **Wall-time waits: about 749.** `waitForTimeout` 495, `setTimeout` promises 249, `sleep(` 5. On top of that, 246
  `waitForFunction`/`waitForSelector` calls swallow their timeout with `.catch(() => {})`.
  - The game already has a game clock: `window.__e2eClock` (src/game/game.ts:99-117, set by `lib/fast.mjs`
    `testClockIn`, used by 11 suites) and `woodrail.simSeconds`. No suite waits on either.

**Proposal:** one module, `scripts/e2e/lib/e2e.mjs`, re-exporting:

- **boot:** `launch({ viewport, touch, clock, saver, pinClocks })` → `{ page, close }`. The test clock is on by
  default, the `__allClicks` counter is installed and page errors are watched. `openMode(page, mode, { seed, flags })`
  resolves once settled.
- **report:** `reporter(suite)` wraps `groups()`, `check` and `finish`; `shot` comes from `lib/shot.mjs`.
- **wait, in game time; every wait throws with a reason:**
  - `frames(page, n)`
  - `settled(page, { ticks, cap })`: throws saying what is still moving
  - `waitGame(page, seconds)`: `simSeconds` up by n
  - `until(page, fn, arg, { game, why })`
  - `run(page, s)`: the named harness shortcut that replaces the 8 `window.__run` copies
- **act:**
  - `tap(page, target, { expect })` **throws on a miss**. Its target is a selector, `{ text }`, `{ depot }`,
    `{ engine }` or `{ piece }`.
  - DOM targets: wait until `elementFromPoint` is the element.
  - World targets: frame with `glideTo`, aim with `lib/aim.mjs` (the game's own `interaction.pick`), retry once, then
    throw with what was under the finger. This is how `touch.mjs:1467` already behaves.
  - `tryTap` is the one explicit, non-throwing version.
  - `drag`, `stroke` and `pinch` are built on `lib/fast.mjs` `touchMoves`.

**Migration order** (each step its own branch; run each touched suite once, before and after):

1. `claude/e2e-lib-1-map-helpers`: the 11 tools with the copied `mapHelpers` block. They are airport, airship,
   depot-tracks, feature-tips, post, power, radio, sandbox-chains, signals, warehouse and water; example
   `tools/e2e/airport.mjs:53-101`. ~550 lines.
2. `claude/e2e-lib-2-dom-taps`: the silent-false DOM taps (engine-names, new-game, locked-tiles, grand, civic,
   gl-lost, life, growth-menu, stats, stickers, paint-picker, school-growth, station-upgrade, train-parts,
   workshop-modes, research-picker, map-sites). ~400 lines.
3. `claude/e2e-lib-3-press-at`: the `pressAt` family (metro, rack, secrets, tech-tree-5, tunnels, ramps, low-bridge).
   ~120 lines.
4. `claude/e2e-lib-4-boot`: the boot, `check`, `settle`, `frames` and `shot` headers in all 67 files. ~1,300 lines.
5. `claude/e2e-lib-5-touch`: `scripts/e2e/touch.mjs` last, group by group. Its helpers are the starting point for the
   shared ones.

In all, about 2,400–2,800 lines removed, and about 500 of the 749 wall waits become waits on a click or on game time.
Risk: a suite that "passed" because its tap silently missed will now fail. That is the point, but budget time to fix
what it shows.

### 5. `stopDistance`: one home for the braking look-ahead

- **Evidence:** `(v * v) / (2 * ACCELERATION)` is written 12 times
  (`grep -rnE '\((\w+(\.\w+)?) \* \1\) / \(2 \* ACCELERATION\)' src --include=*.ts --exclude=*.test.ts`):
  - src/sim/sim.ts 1406, 1453, 1651, 2618, 2703, 2749
  - src/routing/router.ts 875, 1198
  - src/economy/sections.ts 801, 826, 2592
  - src/economy/kit-stops.ts:114
  - `brakeTo` (sim.ts:2897) is the inverse.
  - The margins added differ: none, `+ v*SIM_DT`, `+ 2*v*SIM_DT`.
- **Step a, behaviour-neutral:** add `stopDistance(v)` and `brakeTo` to `src/sim/train-cars.ts` (or a `src/sim/brakes.ts`).
  - Replace each copy, keeping its own margin as written at the call site.
  - Guard: `npm test`, `npm run bench:tick` before and after, and `fuzz:long -- --seeds 40 --seconds 600` with the
    same counts.
- **Step b, a behaviour change, separate and fuzzed:**
  - The sim brakes at `ACCELERATION * quickness` (sim.ts:2400). Quickness is wired in play (src/game/engines.ts:147)
    and the goods engine's is **0.7** (engines.ts:26).
  - None of the 12 look-aheads include quickness, so a goods engine needs about 1/0.7 = 1.43× the distance they allow.
  - Likely effect: a goods engine runs past where a signal, a lift or a stop expected it to be standing. Confirm with
    a fuzz or a scenario before calling it a bug.
  - Branch: `claude/sim-stop-distance-quickness`.

## 7. Mutation testing

**What was run.** Stryker would have to be downloaded, which the sandbox blocks (as it did knip). So a small runner
built from the repo's own vitest did the job instead. Each mutant flips one operator on one line:

- `===`↔`!==`, `<`↔`<=`, `>`↔`>=`
- `&&`↔`||`, `true`↔`false`
- `+`↔`-`, `*`→`/`, `+=`→`-=`, `|=`→`&=`
- `!x`→`x`, `.some`↔`.every`, `Math.max`↔`Math.min`, `??`→`&&`
- a whole number n→n+1

Comments, imports and type-only lines were skipped. The mutants ran on a separate checkout of `3d0becb`, so the game
tree was never touched.

The runner went in two tiers:

- **Tier A:** each mutant against its module's own unit test.
- **Tier B:** one surviving mutant per line, re-run against the broader suites that use the module. For the sim
  modules that was every `src/sim/*.test.ts` except grade-guard, plus `economy/sections.test.ts` and
  `routing/router.test.ts`; `bookings.ts` also got `routing/shadow.test.ts`.

A mutant that hung for 60 s counts as killed (a timeout).

The targets were the shared modules the consolidation passes made: the one copy of each idea, so a weak test there
matters most.

**What the survivors say.** These are gaps, not bugs: each is code whose behaviour could change without any test
noticing.

1. **`train-cars.ts` has no test**, though it's the one copy of `driveOf`, `trainLength`, `engineOf` and `hasEngine`
   (sim, sections, router and economy all call them). Every mutant lived in tier A.
   - The broader suites catch `driveOf` going wrong and `trainLength`'s sum.
   - They don't catch the coupler count (`Math.min(0, n-1)`, `n+1`).
   - They don't catch `engineOf` returning a non-engine or the wrong fallback.
   - They don't catch `hasEngine` always true or always false.

   A 20-line `train-cars.test.ts` kills all 19. **Item 5a.**
2. **`CoverIndex`'s cache key is untested** (occupancy.ts:147-159). The broader suites catch a cover that ignores where
   the train's bogies are (:150-151). They **don't catch the version checks** (:149, the `rev` check tried in tier B).
   Every part of the key survives tier A: `rev`, `sw`
   and `joints` each negated, the bogie loop's `!==` → `===`, `pieceId*8` → `*9`, and `same = true`. A stale cover
   after a switch is thrown or a joint changes would pass `npm test` as far as occupancy.test.ts can tell. This is the
   exact class of bug the consolidation was meant to stop. Test it: cover, throw the switch or move the train, ask
   again, compare with a fresh `CoverIndex`. **Item 5b.**
3. **The train span maths survives, tier B too** (occupancy.ts:119-122, :155-157; only :158's walk start is caught). That covers `cars.length+1` couplers,
   `+frontInset`, `/COUPLER_GAP`, `Math.min(0, span)`, and the bit `2<<path` for `1<<path`. The same span is written 3×
   (§3 item 6); a test against `trainLength()` would pin all three. Folds into item 15.
4. **Bookings** (bookings.ts:41-69, :99). These mutants survive their unit test:
   - `find` by key **or** kind
   - the mask merge's `|=`→`&=`
   - releasing by kind (`!==`; the broader suites catch this one)
   - deleting `byPiece`/`byKey` entries when not empty
   - `free()` with `every(h.key !== key)`

   Releases and the merge are what the redesign's later steps lean on. Add release/merge/free cases. **Item 5c.**
5. **`masksFoul` is unchecked by its callers' tests** (points.ts:116-119). Its mutants survive tier A, and tier B too:
   - `a !== 0 || b === 0` (all but a shared path reads as clear)
   - `gated && lift`
   - `return false` on a foul
   - `(a>>i) & 2`

   Router.ts:309 uses it for which paths foul at a junction, yet sim, sections and router tests all still pass. So
   **no test lays two trains on fouling paths of a crossing or slip and checks the router keeps them apart.** Part of
   item 5c.
6. **`isOn()` is dead in the game.** It is called only by its own test (occupancy.test.ts:56). Its `return true` →
   `return false` survives everything. Add it to the dead-code list (§3); everything else uses `trainOn`.
7. **Equivalent mutants (no fix needed).** Several survivors can't change behaviour, so they need no test:
   - `MAX_OVERLAP_PATHS` 16 → 17, and the 8 mm sampling step → 9 (points.ts:26, :40)
   - loop bounds in `factsOf` where n ≤ 4 (:60-67)
   - `trainOn`'s `except` sentinel −1 → −2 (occupancy.ts:49)
   - the `at = -1` start value (:70)

   Strike these when reading a re-run.
8. **The two modules at 100%** (`lib/words.ts`, `track/math.ts`) are the model for the others: small, pure, each
   branch with a case.
